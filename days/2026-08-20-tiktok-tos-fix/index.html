    2026-08-20 — TikTok App Review: подготовка материалов к ресабмиту¶

    Контекст¶

    19.08.2026 TikTok отклонил App Review. Причины (verbatim из письма): 1. Demo-видео должно показывать полный end-to-end flow интеграции с TikTok (sandbox / mockup). 2. Нет Terms of Service на главной. 3. Нет Privacy Policy на главной. 4. Все выбранные products/scopes должны быть показаны в видео; лишние убрать.

    Что выяснено — реальное состояние прода¶

    • Terms of Service уже на проде: https://triangula.app/terms (HTTP 200, тёмная тема, 13 секций, обновлён 02.08.2026). ✅ Закрывает причину 2.
    • Privacy Policy уже на проде: https://triangula.app/privacy (HTTP 200, 10 секций). ✅ Закрывает причину 3.
    • Footer главной уже содержит ссылки Research / Privacy / Terms + hello@triangula.app. ✅
    • Локальный /opt/triangula-api/public/ отставал от прода (не содержал privacy/terms/research и ссылки) — синхронизирован с прода и закоммичен в ветку sync-prod-to-08020 (commit 4c31b85).

    Scopes (причина 4)¶

    Текущая заявка: video.upload, video.publish, user.info.basic. В коде (scripts/tiktok_auth.py — SCOPES, tiktok_post.py — /v2/video/upload/) используются все три: - video.upload — загрузка - video.publish — публикация (в скилле: Direct publish требует audit) - user.info.basic — OAuth, имя/аватар для сессии

    Вывод: лишних scopes нет — удалять не нужно. Надо лишь PROДЕМОНСТРИРОВАТЬ их в живом видео. Причина отказа №4 относится к видео, а не к набору scopes.

    Что НЕ сделано (блокер ресабмита) — причина 1¶

    Текущее demo-видео /tmp/tiktok_demo/triangula_tiktok_demo.mp4 (440K, PIL-мокапы 8 слайдов, 32 сек) — статичный слайдшоу, TikTok просит живой end-to-end flow. Нужен скринкаст/Playwright с реальным sandbox: - Playwright установлен (venv Hermes, @playwright/cli). - Точно: переснять не могут автоматически без доступа к аккаунту-самбуру; TikTok sandbox требует добавить до 5 тестовых юзеров вручную. Это ручная/отдельная задача.

    Файлы¶

    • Лендинг+API: /opt/triangula-api/ (ветка sync-prod-to-08020).
    • Скрипты TikTok: /root/.hermes/skills/social-media/tiktok-automation/scripts/ (tiktok_auth.py, tiktok_post.py, gen_demo_video.py).
    • Вики-порядок задеплоя/форм: tiktok-automation/SKILL.md §App Review Submission.

    4. Ресабмитить.

    Scopes в коде (причина 4)¶

    • tiktok_auth.py:24 — SCOPES = "video.upload,video.publish,user.info.basic".
    • tiktok_auth.py:35 — redirect URL https://www.tiktok.com/v2/auth/authorize/?scope=... (consent-экран показывает все три).
    • tiktok_post.py:54 — POST /v2/video/upload/ используется в upload_video().
    • user.info.basic — через /v2/user/info/ (через Login Kit, имя/аватар для UI сессии). Используется косвенно — нужно показать в видео как минимум consent-экран OAuth, где перечислены все три scope.
    • Лишних scopes нет. Демо должно показать consent-экран с галочками всех трёх → upload → publish confirmation.

    Технические требования к записи: - Разрешение: 1080×1920 (вертикальный) или 1920×1080 (горизонтальный) — на усмотрение TikTok Review, оба принимают. - Без монтажных склеек в критических моментах (consent-экран и upload — real-time, без ускорения). - Voice-over опционален; обязательны текстовые оверлеи (для неанглоязычных ревьюеров). - Длина: 60–180 сек (TikTok лимит).

    Что нужно сделать Сергею руками¶

    1. Подготовить sandbox-аккаунты (причина 1): - В TikTok Developer Console → App → Sandbox → Add Sandbox User (до 5 штук). - Использовать свой личный TikTok-аккаунт (fravart7@gmail.com → TikTok там же). - Получить CLIENT_KEY / CLIENT_SECRET из App → Credentials. - В /root/.hermes/.env.tiktok (или ~/.bashrc) — экспортировать: 

    export TIKTOK_CLIENT_KEY=sbaw...      # из App → Sandbox
export TIKTOK_CLIENT_SECRET=...        # sandbox secret
export TIKTOK_REDIRECT_URI=https://triangula.app/callback
    Текущий sandbox vs production secret различаются — обязательно sandbox-ключи.

    2. Записать demo-видео (Playwright + OBS или ручная запись экрана): - Вариант A (проще): ручная запись экрана через OBS Studio на локальной машине, открыть triangula.app в браузере, нажать «Login with TikTok», пройти OAuth, выбрать фото, залить, дождаться «Published». Камера лица не нужна. - Вариант B (скриптом): Playwright скрипт в /tmp/tiktok_demo/ (есть опыт из предыдущих сессий) + ffmpeg склейка слайдов с реальными скриншотами. НЕ делать сейчас — Сергей не кодер, ручной записи достаточно. - Записать в MP4 1080p, длительность 90–120 сек.

    3. Заполнить форму App Review: - App URL: https://triangula.app - Terms of Service URL: https://triangula.app/terms (без .html — CF редиректит). - Privacy Policy URL: https://triangula.app/privacy. - Demo video: загрузить MP4 (см. п.2). - Products: Login Kit + Content Posting API (оставить как есть). - Scopes: оставить video.upload, video.publish, user.info.basic (все три реально используются, лишних нет). - Описание интеграции: упомянуть «end-to-end OAuth consent, photo upload, video publish via /v2/video/upload/».

    4. После одобрения (отдельная задача): - python3 /root/.hermes/skills/social-media/tiktok-automation/scripts/tiktok_auth.py → авторизация под sandbox-юзером → access_token. - python3 tiktok_post.py /path/to/video.mp4 "Title" → тестовая публикация. - Мержить sync-prod-to-08020 → main (или перебазировать main на 4c31b85) — почистить историю.
